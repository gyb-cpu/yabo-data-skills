# 连接配置与使用

## 安装与配置

将技能根目录 `.env.example` 复制到使用项目的根目录，命名为 `.env.shenergy`，由环境负责人在本机填写。每个使用者独立配置；模板只含空值和常见默认端口，不含真实地址或凭据。项目已有安全的密钥管理或明确配置位置时优先使用项目规定，不覆盖已有文件。实际配置不得打包、提交、发送或写进产物；将 `.env.shenergy` 加入项目忽略规则或本地私有排除规则。

变量含义：`TABLEFORGE_URL` 为建表工匠地址，`TABLEFORGE_USERNAME`/`TABLEFORGE_PASSWORD` 或 `TABLEFORGE_TOKEN` 为实际认证资料；以平台支持方式为准，不假设全部必填。`SOURCE_MYSQL_*` 是源端 MySQL 连接参数，`TARGET_PG_*` 是目标 PostgreSQL 连接参数；`*_SSL_MODE` / `TARGET_PG_SSLMODE` 按实际驱动和服务器支持的取值填写，不能把模板空值理解为已配置 TLS。MySQL 和 PG 使用各自只读账号。多源库或环境的配置由项目约定，无法唯一选择时先明确目标，不将单组配置默认为所有省份。

## 运行时规则

1. 确认本次任务范围与授权；离线、禁止读凭据或禁止联网时不读取配置、不连接。配置文件存在不是联网、平台修改、写库或执行 SQL 的授权。
2. 仅在某阶段确实需要对应连接、且读取和访问获授权时读取对应变量；禁止输出整个配置、值、连接 URI、命令行密码、认证头、环境变量转储或原始异常中的凭据。配置作为数据解析，不作为 shell 脚本执行；使用支持环境变量/标准输入/受保护认证文件的驱动或客户端传递认证信息。优先复用本地已有的适配器、连接器或平台会话，不假定 API、登录流程、驱动或 CLI 已安装。
3. 配置文件缺失、缺项或访问失败时，仅报告缺失变量名、阶段及不含秘密的原因；不得输出值。继续可独立完成的工作，将依赖该连接的结果标为待验证；不得猜测地址、凭据、字段或声称已连通。
4. 平台：按实际认证方式访问，查重并取得字段匹配与平台原始 DDL；新增词条等写操作仅限本次授权范围。平台地址与查询结果以当次配置和实际响应为准。
5. 数据库：源 MySQL 与目标 PG 仅按授权执行只读元数据和数据核查，确认当前库、schema、对象、字段类型、索引、日期范围、更新/删除机制及映射；查询只取完成任务所需内容。目标 DDL、函数或回算的写入是另一个操作范围，不因有连接信息而自动授权。执行记录不含凭据或敏感连接串。
6. 本技能负责经授权的连接和取证。函数生成、改写或审查时调用 `pg-function-craft`，该技能仍只负责离线 SQL 工程，不让它连接数据库或执行 EXPLAIN；将脱敏的结构和业务证据交给它。未安装时标记依赖缺失并提示安装；在安装并调用前，函数生成、改写或审查阶段阻塞，其他不依赖它的阶段可继续；不得声称已使用该技能或其检查器。业务事实不足时照常阻塞相关函数实现。
