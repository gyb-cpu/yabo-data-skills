# 产物契约

在用户指定的省份/业态根目录下组织；用户指定其他位置时遵从。只创建有内容的阶段产物，并在每份文件标注候选、已执行或未验证状态及证据；禁止把缺失资料伪装成定稿。

首次开发（`bootstrap`）的产物以 `首次开发.md` §4 的固定清单为准，并用 `scripts/check_shenergy_artifacts.py --kind bootstrap --json <省份业态目录>` 校验；下面的完整结构适用于 `full` 与 `maintenance`。

```text
<省份业态>/
├─ README.md
├─ 参考资料/
│  ├─ <任务当天快照>.xlsx
│  ├─ 指标字段来源对照表.md
│  └─ 指标字段来源对照表.csv
├─ DDL/<省份><业态><表数>表_建表语句.sql
├─ 计算脚本/README.md
├─ 计算脚本/<目标表名>.sql
└─ 复核验证/
   ├─ <省份业态>_待人工确认清单.md
   ├─ <省份业态>_待建字段清单.md
   ├─ <省份业态>_平台补录与变更记录.md
   ├─ <省份业态>_平台原始DDL.sql
   ├─ <省份业态>_字段映射与fill_mode清单.md
   ├─ <省份业态>_源表登记与同步清单.md
   ├─ <目标表名>_spec.json
   ├─ <省份业态>_评审报告.md
   ├─ <省份业态>_执行与验收.sql
   ├─ <省份业态>_验收报告.md
   └─ <省份业态>_血缘登记与校验.sql
```

快照保留来源、日期、版本，不覆盖原文件。平台原始 DDL 原样留存，纠偏后的 PostgreSQL DDL 另存，并通过 `scripts/check_shenergy_artifacts.py --kind ddl --spec <spec.json> --json` 校验。SQL 文件标明目标环境、用途、只读或写入、执行前提和状态；不写凭据。函数头必须是 `AS $function$` 之后的函数体内块注释，新建 DWD 函数 `*output` 固定写 `-1参数异常, >=0影响行数`（既有函数保留原状态码 `0` 时写 `-1参数异常, 0正常`），并以 `pg_get_functiondef` 可导出为验收条件；提交前通过一键双检门禁 `scripts/check_shenergy_artifacts.py --kind func --with-pg-checker --spec <spec.json> --json`（内部联动 `scripts/check_sql_output.py --json`，合并无重叠双层检查结果）或分别留存两项检查器 JSON 输出。只有结构、口径和权限足以确定时才生成具体可执行脚本；`<省份业态>_执行与验收.sql` 与 `<省份业态>_血缘登记与校验.sql` 可先由 `scripts/generate_validation_sql.py --spec <spec.json>` 生成标准骨架再按实际表名与口径补齐。

## 表级函数规格卡（Function Spec）

阶段 4 定稿 DDL 后、阶段 5 编写计算函数前，每张目标表在 `复核验证/` 沉淀一份脱敏的 `<目标表名>_spec.json`（不含连接串、凭据或原始数据），作为向 `pg-function-craft` 交接并驱动离线校验与验收 SQL 生成的唯一结构化输入：

```json
{
  "schema_version": "1.0",
  "target_table": "dwd.dwd_elec_settlement_d96",
  "function_name": "dwd.f_dwd_elec_settlement_d96",
  "grain": "day96",
  "date_col": "target_date",
  "unit_col": "transactionunit",
  "target_engine": "pg12+",
  "mode": "generate",
  "return_contract": "row_count",
  "legacy": false,
  "increment_mode": "update_time",
  "business_keys": ["province", "company", "transactionunit", "target_date", "timeperiod"],
  "insert_columns": [
    "province", "company", "transactionunit", "target_date",
    "target_yearmonth", "timeperiod", "settlement_energy"
  ],
  "metric_columns": ["settlement_energy"],
  "sources": [
    {"table": "ods.src_settlement_d24", "role": "driver", "incremental": true},
    {"table": "dim.dim_public_price", "role": "supplement", "incremental": false}
  ],
  "blood_batch": "2026-11-27_batch01"
}
```

- 必选字段：`target_table`、`function_name`、`grain`（`day96` / `day` / `month`）、`business_keys`、`insert_columns`、`sources`（`role` 为 `driver` 或 `supplement`）；均通过 `scripts/check_shenergy_artifacts.py --kind spec --json` 校验。
- 硬约束：`insert_columns` / `business_keys` / `metric_columns` 不得包含 `ext_1`–`ext_10`；`day96` 必须包含 `timeperiod`；`increment_mode` 为 `update_time` 时每个 `driver` 源必须显式声明 `"incremental": true`（对应 `INC-15`）。

## 字段对照

Markdown 按目标表分节，记录快照文件、sheet、区块与行、数据证据和状态；每行对应目标物理字段，列出英文名称、中文名称、BI看行、来源表、来源字段和口径。原文口径与实现差异分开记录，不把实现推断写成原文。

CSV 骨架优先由 `scripts/parse_bi_snapshot.py <snapshot.xlsx> --out-csv <out.csv>` 提取（自动物理忽略 I/J/K 并展开合并单元格），采用无 BOM 的 UTF-8 与 LF 换行，表头和顺序固定为：

```csv
目标表,区块,物理序号,英文名称,中文名称（BI看）,库注释,BI看行,取值来源表,取值来源表字段,口径/说明,单位,缺值规则
```

定稿前后均须通过 `scripts/check_shenergy_artifacts.py --kind csv --json` 校验。Markdown 与 CSV 共用同一来源记录；阶段一允许未知字段或待定序号明确标记（缺省可填 `待确认`），定稿后逐物理列核对 DDL。多来源、公式、常量、无来源和待确认应如实标注，不按名称推断字段。

## 补充清单

字段映射与 fill_mode 清单另存，不改上面的 12 列契约。逐目标字段记录：目标表/字段、来源表/字段、源与目标粒度、关联业务键、过滤和转换规则、增量触发键、fill_mode 及其含义、空值/零值规则、证据和状态。fill_mode 取实际平台或项目定义并保留原值；定义缺失则待确认，不虚构枚举。

源表登记与同步清单逐表记录：L 单元格（区分 `named` / `pending` / `empty`）或额外依赖证据、用途、源端与目标读取位置、同步方式、覆盖范围、最新核实时间、状态和缺口；未知与空白分别标识。待建字段、平台变更清单记录名称、类型、依据、查重结果和执行状态。

待确认清单逐项写明问题、影响字段、证据、需要的业务决定和阻塞阶段。评审与验收报告逐表记录检查范围、执行环境和时间、方法、结果、差异及是否通过；未执行单独标识，并须包含 `artifacts`、`gates`、`open_questions`、`next` 与静态检查/编译验证留痕，交付前通过 `scripts/check_shenergy_artifacts.py --kind report --json` 校验。血缘文件记录两张表各自的登记及校验范围、业务键、批次、精确回滚范围，禁止假定历史记录可删除。

根 README 给出目标清单、快照与版本、阶段状态、产物索引、已部署/已回算/已验收状态和待办；计算脚本 README 逐表写函数签名、依赖、运行方式、增量口径、限制与实际状态。计算脚本的字段映射和 `INSERT`/`SELECT` 不包含 `ext_1`–`ext_10`；扩展字段仅作为 DDL 预留列记录，不生成空值占位。每阶段总结 artifacts、gates、open_questions、next，所有状态附可复核证据；技能自身离线完整性由 `scripts/verify_offline.py --json` 校验。
