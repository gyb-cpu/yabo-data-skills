# 产物契约

在用户指定的省份/业态根目录下组织；用户指定其他位置时遵从。只创建有内容的阶段产物，并在每份文件标注候选、已执行或未验证状态及证据；禁止把缺失资料伪装成定稿。

```text
<省份业态>/
├─ README.md
├─ 参考资料/
│  ├─ <任务当天快照>.xlsx
│  ├─ 指标字段来源对照表.md
│  └─ 指标字段来源对照表.csv
├─ DDL/<省份><业态><表数>表_建表语句.sql
├─ 计算脚本/README.md
├─ 计算脚本/<目标表名>.sql
└─ 复核验证/
   ├─ <省份业态>_待人工确认清单.md
   ├─ <省份业态>_待建字段清单.md
   ├─ <省份业态>_平台补录与变更记录.md
   ├─ <省份业态>_平台原始DDL.sql
   ├─ <省份业态>_字段映射与fill_mode清单.md
   ├─ <省份业态>_源表登记与同步清单.md
   ├─ <省份业态>_评审报告.md
   ├─ <省份业态>_执行与验收.sql
   ├─ <省份业态>_验收报告.md
   └─ <省份业态>_血缘登记与校验.sql
```

快照保留来源、日期、版本，不覆盖原文件。平台原始 DDL 原样留存，纠偏后的 PostgreSQL DDL 另存。SQL 文件标明目标环境、用途、只读或写入、执行前提和状态；不写凭据。只有结构、口径和权限足以确定时才生成具体可执行脚本。

## 字段对照

Markdown 按目标表分节，记录快照文件、sheet、区块与行、数据证据和状态；每行对应目标物理字段，列出英文名称、中文名称、BI看行、来源表、来源字段和口径。原文口径与实现差异分开记录，不把实现推断写成原文。

CSV 采用 UTF-8，表头和顺序固定为：

```csv
目标表,区块,物理序号,英文名称,中文名称（BI看）,库注释,BI看行,取值来源表,取值来源表字段,口径/说明,单位,缺值规则
```

Markdown 与 CSV 共用同一来源记录；阶段一允许未知字段或待定序号明确标记，定稿后逐物理列核对 DDL。多来源、公式、常量、无来源和待确认应如实标注，不按名称推断字段。

## 补充清单

字段映射与 fill_mode 清单另存，不改上面的 12 列契约。逐目标字段记录：目标表/字段、来源表/字段、源与目标粒度、关联业务键、过滤和转换规则、增量触发键、fill_mode 及其含义、空值/零值规则、证据和状态。fill_mode 取实际平台或项目定义并保留原值；定义缺失则待确认，不虚构枚举。

源表登记与同步清单逐表记录：L 单元格或额外依赖证据、用途、源端与目标读取位置、同步方式、覆盖范围、最新核实时间、状态和缺口；未知与空白分别标识。待建字段、平台变更清单记录名称、类型、依据、查重结果和执行状态。

待确认清单逐项写明问题、影响字段、证据、需要的业务决定和阻塞阶段。评审与验收报告逐表记录检查范围、执行环境和时间、方法、结果、差异及是否通过；未执行单独标识。血缘文件记录两张表各自的登记及校验范围、业务键、批次、精确回滚范围，禁止假定历史记录可删除。

根 README 给出目标清单、快照与版本、阶段状态、产物索引、已部署/已回算/已验收状态和待办；计算脚本 README 逐表写函数签名、依赖、运行方式、增量口径、限制与实际状态。每阶段总结 artifacts、gates、open_questions、next，所有状态附可复核证据。
