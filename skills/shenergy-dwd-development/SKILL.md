# 申能省份 DWD 开发

本技能包含独立分发的流程和交付规范：执行前读取 [流程与门禁](references/流程与门禁.md)；创建产物时读取 [产物契约](references/产物契约.md)；开发函数、执行或验收时读取 [函数与验收](references/函数与验收.md)；需要访问建表工匠或数据库时读取 [连接配置](references/连接配置.md)，以随包 `.env.example` 配置运行环境。实际项目规则及用户最新要求优先，具体省份、业态、业务表、源表和字段以当次资料及实查为准，不把历史案例复制成当前事实。

涉及 `timeperiod` 的目标表，时段换算方向不是可选项：源为 24 点必须展开为 96 点（电量 `/4.0`、电价沿用），不得建 `_d24`，也不得把 96 点源降采样后复制回 96 槽。判定方法与验算见 [函数与验收](references/函数与验收.md) §2.1。

另外三条同样不可自行发挥，写函数前先读：

- **时段骨架**只能取自 `dim.dim_timeperiod_change`，禁止 `generate_series` 拼字符串自造（§2.1）。
- **增量**按 `update_time` 水位线收 `date[]` 变化集合，删除与重算同集合，禁止扩成 `min/max` 区间（§2.4）。
- **既有函数的参数校验返回值、`EXCEPTION` 包装、头部字段、观测点**都要保留，不得把 `RETURN -1` 改成 `RAISE EXCEPTION`（§2.5）。

改 `pg-function-craft` 覆盖的排版时注意：该技能的 F-32 只校验同层列表项，跨行 `CASE` 与拆开的算术式按 06 规范展开不会误报。不要为了通过检查器把表达式压成超长单行。

## 输入与边界

确认省份、业态、工作区、任务日期、已有对象、新建或改造范围、用户授权的读取与写入范围。先查本地项目规则、快照及现有材料；凭据只在需要时从项目指定配置读取，禁止输出、复制到交付物或技能。旧导出只证明文件所载内容；数据库现状要以当次查询为准。按 `observed`、`inferred`、`unverified` 区分已证事实、推断与未验证项，标文件行号或工作簿单元格。

用户规定离线、只读或本地演练时遵守该次边界，不以本技能放宽权限。用户要求实际开发时，按授权执行只读探查、平台和数据库操作，运行前明确目标对象及影响；未经授权不写数据库、平台或调度。区分本地候选、事务内验证并回滚、已部署、已回算、已验收，不凭静态通过声称运行通过。

## 目录和交付物

参照随包产物契约，在用户指定的省份/业态根目录下建立以下结构；多业态同省时避免覆盖。只创建已进入阶段的真实产物，缺证项记入待确认清单，不创建空 SQL 冒充完成。用户另定目录时采用用户路径。

```text
<省份业态>/
├─ README.md                         # 对象清单、证据、阶段与实际部署/验收状态
├─ 参考资料/
│  ├─ <任务当天快照>.xlsx            # 原文件及日期，按需获取或引用
│  ├─ 指标字段来源对照表.md          # 分目标表的指标、来源与口径
│  └─ 指标字段来源对照表.csv         # 与 MD 同源；定稿后逐物理列对应 DDL
├─ DDL/
│  └─ <省份><业态><表数>表_建表语句.sql  # 有证据的本地候选/定稿，标注状态
├─ 计算脚本/
│  ├─ README.md                      # 各表来源、签名、调用、已知限制与状态
│  └─ <目标表名>.sql                 # 每张表一个函数文件，勿伪造缺失实现
└─ 复核验证/
   ├─ <省份><业态>_待人工确认清单.md
   ├─ <省份><业态>_待建字段清单.md
   ├─ <省份><业态>_平台补录与变更记录.md
   ├─ <省份><业态>_平台原始DDL.sql    # 平台产出后原样留档
   ├─ <省份><业态>_字段映射与fill_mode清单.md
   ├─ <省份><业态>_源表登记与同步清单.md
   ├─ <省份><业态>_评审报告.md
   ├─ <省份><业态>_执行与验收.sql    # 阶段需要且证据充分时生成
   ├─ <省份><业态>_验收报告.md        # 已执行结果或明确标为待验证
   └─ <省份><业态>_血缘登记与校验.sql # 结构和范围已核定时生成
```

按需在 `复核验证/` 放源表登记、映射覆盖、验证脚本、报告、部署记录、备份和历史文件；区分只读、会写库及历史一次性脚本，禁止把未经核准的候选标成可运行定稿。历史快照保留版本，不覆盖原件。字段对照的 MD/CSV 格式及 12 列原样表头见 [产物契约](references/产物契约.md)；阶段一先产出可得内容，后续探源补全并保持两份同源。另在字段映射清单记录源列、目标列、业务键、转换、增量键、证据和 fill_mode，保留未确认项。

## 阶段流程与门禁

1. **口径确认（SOP §1）**：只用任务当天快照的 `BI看`，按 A 列省份和业态筛选；依据当期表头解释 A–H、L，不读取 I/J/K。登记文件、日期、行号、合并范围；L 一格多表逐表登记，L 为空、待补充、已具名、未读取分开记。识别指标、来源、粒度、公式、单位、替换顺序和缺值规则，产出字段对照及待确认清单。当天快照缺失则正式口径阻塞；历史材料仅能在明确标注后作演练。历史材料如要求读取 I/J/K，以本次入口规则为准；当期表头与固定列号不一致时不机械套用，记录无法消解的冲突。
2. **源库探查与字段映射（§2）**：登记 L 列全部具名源表和 SQL 中的额外依赖，保留来源单元格、用途、源端和目标端读取位置、同步方式与状态；探查字段类型、数据范围、NULL/空串/0、`update_time`、`deleted`、时段粒度、主体映射与一对多。按授权访问源端和目标端；不可访问则标待核。L 空白不能当同步清单已完成。字段来源不明、业务口径冲突不猜测。
3. **命名及平台补录（§3）**：整理待建字段与命名依据，优先复用跨省同义字段与平台既有词条；检查语义、冲突与长度。平台字典和字段库先查重；在用户授权范围内登记并重跑建表面板，保留补录与覆盖证据。平台不可用时保留待办和候选名，不宣称覆盖完成。
4. **建表 DDL（§4）**：依据定稿字段清单、平台原始 SQL 和项目类型规范生成 PG DDL、字段注释及主键，逐列比对名称、顺序、类型、精度、默认值、非空和约束；业务列后是 `ext_1`–`ext_10`，最后 `updated_time`。核对 `id` 生成机制与插入方式。已有表先比对真实结构并设计迁移；不得把候选当作已部署或默认重建已有表。
5. **计算脚本（§5）**：每表独立确定目标粒度、业务键、源依赖、口径、缺值及原函数签名。**写函数前先调用 `pg-function-craft`**，把 `scripts/check_sql_output.py --json` 的实际输出留存为交付证据；该技能是必调项，不是可选工具（可选的是 `sqlglot`、`sqlfluff` 一类包外工具）。未安装时标记该依赖缺失并阻塞函数生成、改写或审查，其他独立阶段可继续；检查器 `ok: true` 只代表表格规则通过，仍须做数据库编译验证，两步都完成才算静态检查通过。保留既有外部签名与必要错误处理。多源独立驱动须覆盖；有 `timeperiod` 的新目标按项目规范使用 96 点，各源在最终关联前达到目标粒度，24→96 的量值按口径守恒。稀疏增量保留实际变更日期/月集合，删除与重建共用该集合；显式区间独立处理，逻辑删除、真实 0、无来源分别验证。按表把 SQL 写入 `计算脚本/`，缺证据则列阻塞而非编造。
6. **运行与回填（§6）**：仅在用户授权的目标环境和范围内执行。核对实际 DDL、函数版本、源表同步、时段维表及主体映射；区间重跑前核查待重建主体×日期覆盖和一对多、备份目标区间、准备回滚，防止全区间删除后源缺失造成丢数。分别记录部署、事务试跑、回滚或提交、首次回填及增量结果；不得仅凭函数返回 0 判定成功。
7. **验收对账（§7）**：按实际口径核验结构、业务键、行数/范围、时段、源目标量值、缺失及重复、真实 0、空值和幂等；稀疏增量和显式区间分别检查。在可比口径与相同范围下做源目标双向差集、重复业务键检查，期望均为 0；口径变化或明确允许的缺口须记录差异与业务确认，不能机械宣称等价。留存 SQL、执行环境、范围、结果与例外；未执行则标未验证，不把静态结果说成动态验收。
8. **血缘登记（§8）**：先确认 `dim.dim_dictionary_blood` 与 `dim.dim_dictionary_blood2` 各自实际结构、已有有效记录、作用范围和批次；按各自结构生成同一批字段血缘，按随包流程分别核对两表字段与注释、遗漏、重复、批次和两表成对情况：差异类检查预期 0 行，状态分布与批次数量按实际核对。只在获授权时登记，留存登记和校验结果；不可套用安徽历史数量或旧回滚谓词。
9. **评审交付（§9）**：检查口径、结构、语义、增量、粒度、性能证据、待确认项和各阶段产物；更新根目录与计算脚本 README。记录快照版本、实际数据库与本地差异、未执行事项以及每项证据，不用历史报告代替当前状态。

## 执行与交付契约

按用户范围从相应阶段开始；每阶段交代 `artifacts`（文件路径）、`gates`（通过/阻塞/未验证与证据）、`open_questions`（缺口及影响）、`next`。阻塞不影响独立的只读盘点和可生成的部分对照，但不得把缺口静默补成事实。最终交付具体文件和阶段状态；案例中的列数、表数、时间、已部署状态均不能充当新省份验收基线。

历史 SOP 的旧列号、`min/max` 模板和案例可能过时：当期表头、明确的最新用户要求、项目规范和已验证对象优先；无法消解的业务冲突记录并停止相关实现。回算前按随包流程执行覆盖检查、备份及恢复准备。
