# 工程与函数结构规范（参考来源整理）

本文件是「工程安全与函数结构层」的规范来源接入，处理对象选型、权限边界、`search_path`、
事务边界、错误契约、会话状态与迁移约束。

- 规则性质：`normative`（规范要求）；来源类型：`reference`（外部参考）。
- **不是对任何个人或输入的描述**：不产生 `observed` 结论，也不附带任何语料计数或置信度。
  用户当次输入中没有出现 `SECURITY DEFINER` 或 `SET search_path`，只能说明“这段代码没有用到”，
  不能据此推断个人偏好。
- **没有运行**任何数据库、权限查询、`EXPLAIN`、格式化或审查工具；不声称任何配置“已验证安全”。
- 与 `references/01-基线规范.md` 冲突时以 `01` 为准；其余冲突（含与项目书面约定）按
  `00-风格与边界.md` §6 的优先级处理。本文件把 `01` 的默认值展开为工程检查项，并吸收外部
  来源中可移植的部分。

## 2. 对象选型：函数、过程、触发器函数（ENG-01）

| 形态 | 事务控制 | 调用方式 | 返回值 | 适用 | 9.4/GP 6.6 |
|---|---|---|---|---|---|
| 普通函数 | 不能 `COMMIT`/`ROLLBACK` | `SELECT` | 标量/复合/集合 | 计算、查询、ETL 步骤 | 可用 |
| 集合返回函数 | 同上 | `SELECT ... FROM f()` | `SETOF`/`TABLE` | 流式结果、报表 | 可用 |
| 触发器函数 | 跟随触发语句的事务 | 由触发器调用，不能直接调用 | `trigger` | 审计、约束、派生列 | 可用 |
| 过程 | 可 `COMMIT`/`ROLLBACK`（`[11+]`） | `CALL` | 无返回值/`OUT` | 多事务编排、批处理 | **不可用** |

判断顺序：

1. 需要跨事务提交/回滚 → 只有 `[11+]` 过程能做；9.4 必须把事务控制交给调用方。
2. 需要返回行集 → 函数 + `RETURNS TABLE`/`SETOF`，不要用临时表 + 二次查询模拟。
3. 需要 `NEW`/`OLD` → 触发器函数；不要把触发器逻辑写成普通函数再由触发器转调，除非有明确复用需求。
4. 只是封装一条 SQL → 优先 SQL 语言函数，可能内联；不要为了“统一”强制 PL/pgSQL。

## 3. 签名、返回形态与契约（ENG-02、ENG-03、ENG-16）

### 3.1 签名

- 参数名、类型、顺序、默认值是调用方契约；改写不得擅自变更。
- 默认参数在 9.4 可用；新增默认参数可能造成重载歧义，需检查同名函数。
- 命名参数调用（`f(p_id => 1)`）依赖参数名；改参数名会破坏调用方。
- `CREATE OR REPLACE FUNCTION` 不能改变返回类型，也不能改变已有参数的类型/名称（以目标版本
  文档为准）；需要改契约时走显式迁移，并在输出中标注“需批准”。

### 3.2 返回形态

| 形态 | 写法 | 适用 | 注意 |
|---|---|---|---|
| 标量 | `RETURNS bigint` | 计数、状态码、单值 | 返回码语义要写清 |
| 复合 | `RETURNS demo.t_type` | 固定结构 | 类型变更影响调用方 |
| `SETOF` | `RETURNS SETOF demo.t_table` | 返回整行 | 列依赖强；`SELECT *` 风险 |
| `TABLE` | `RETURNS TABLE (a bigint, b text)` | 明确列集 | 列名即契约 |
| `OUT`/`INOUT` | `OUT o_cnt bigint` | 多返回值 | 调用方式与列名要对齐 |
| `VARIADIC` | `VARIADIC arr text[]` | 可变参数 | 重载解析复杂，慎用 |
| `trigger` | `RETURNS trigger` | 触发器 | 必须返回 `NEW`/`OLD`/`NULL` |

- 集合返回函数要说明：是否保证顺序、是否有重复行、调用方 `LIMIT` 能否下推。
- 用 `text` 返回 JSON/CSV 会丢失类型与 NULL 语义；除非是明确的序列化契约，不要这样做。

## 4. 权限与 `search_path`（ENG-04～ENG-07、ENG-21、ENG-22、ENG-24）

### 4.1 `SECURITY INVOKER` 与 `SECURITY DEFINER`

- 默认 invoker：权限按调用方检查，RLS 也按调用方生效。
- definer：按函数属主权限执行；能绕过 RLS（`[9.5+]`）与部分权限检查，必须证明必要性。
- definer 的属主应是专用低权限角色，不是 superuser，也不是业务 schema 的 owner。

### 4.2 `search_path` 的正确写法

```sql
-- *name : f_secure
-- *function : 按主键读取并校验权限
-- *input : 1:主键
-- *output : 1:命中行数
-- *author : <team>
-- *CreateDate : 2026-01-01
-- *UpdateDate : 2026-01-01
CREATE OR REPLACE FUNCTION demo.f_secure(p_id bigint)
RETURNS bigint
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, demo, pg_temp
AS $function$
...
$function$;
```

要点：

- 显式列出 `pg_catalog`，再列受信业务 schema，最后显式写 `pg_temp`。
- 只写“排除 `pg_temp`”不够：未显式列出时，`pg_temp` 对表和类型名默认先于 `search_path`
  中的 schema 被搜索；只有显式定位才能把它压到受信 schema 之后。
- `public` 在 PG 15 之前默认对 `PUBLIC` 开放 `CREATE`，不能当作可信 schema；需要时显式列入并
  确认写权限已收紧。
- 空 `search_path`（`SET search_path = ''`）也是一种安全写法，但要求函数内所有对象全限定；
  与上面二选一，不要混用。
- 不要写 `SET search_path = public, pg_temp`：`public` 不可信，且没有显式 `pg_catalog`。

### 4.3 权限检查清单

- [ ] 函数属主是专用角色，不是 superuser。
- [ ] `REVOKE EXECUTE ON FUNCTION ... FROM PUBLIC`（默认 `PUBLIC` 可执行）。
- [ ] 只授需要的角色；不要 `GRANT ALL ON ALL FUNCTIONS IN SCHEMA`。
- [ ] 序列权限单独授予（`USAGE`/`SELECT`），不要假设表权限覆盖序列。
- [ ] 已授 schema `USAGE`，并同时授对象 `SELECT`/`EXECUTE`；需要未来对象时配置
      `ALTER DEFAULT PRIVILEGES`（ENG-24）。
- [ ] 权限证据来自 `pg_proc.proacl`、`pg_class.relacl` 或实际授权记录，不是函数文本。
- [ ] `pg_get_functiondef` 不导出 `GRANT`/`REVOKE`/`COMMENT`/属主；文本缺失不能证明未授权。

### 4.4 RLS（ENG-21）

- RLS 是 `[9.5+]`；9.4 没有 `CREATE POLICY`/`ENABLE ROW LEVEL SECURITY`。GP 6.6 的支持情况
  `[GP-待验证]`，不要按社区 PG 推断。
- definer 函数默认以属主身份运行，通常会绕过 RLS；如果业务依赖 RLS 做租户隔离，必须在函数内
  显式校验调用方身份，或改用 invoker + 视图。
- 策略中调用函数会逐行求值；把 `auth.uid()` 之类替换为 `(SELECT ...)` 的写法是 Supabase 平台
  经验，本技能没有 `auth.uid()`，不要照抄。
- 策略列要有索引；否则每行策略检查可能退化为扫描（`PERF-01`）。

## 5. 事务、异常与错误契约（ENG-09、ENG-11）

### 5.1 事务边界

- 函数体没有显式事务控制；整次调用在调用方事务（或语句级子事务）内。
- `EXCEPTION` 块是子事务：进入块会建立保存点；块内语句失败时回滚到保存点，再由 handler 决定
  重抛或继续。子事务有额外代价（`PERF` 层面属 `workload-required`）。
- 9.4 不能 `COMMIT`/`ROLLBACK`；`[11+]` 过程才可以。
- 不要在函数内做长等待、外部 HTTP 调用或用户交互；锁会一直持有到事务结束。

### 5.2 错误契约设计

三选一，写进头部与文档：

| 契约 | 适用 | 写法 | 风险 |
|---|---|---|---|
| 返回码 | 调度型 ETL、可预期失败 | `0` 成功、`-1` 参数异常等 | 调用方可能忽略；需文档化 |
| 异常 | 不可恢复错误、违反约束 | `RAISE EXCEPTION ... USING ERRCODE` | 调用方必须处理；文本可能被依赖 |
| 混合 | 参数错误返回码，系统错误抛异常 | 明确分界 | 容易变成“都返回 -1”或“都抛异常” |

要求：

- 不要用 `WHEN OTHERS THEN NULL` 或“返回 0 表示失败”制造假成功（`REV-C01`）。
- 需要保留原始 `SQLSTATE` 时，用 `GET STACKED DIAGNOSTICS` 取 `RETURNED_SQLSTATE`，再
  `RAISE ... USING ERRCODE = v_state`；只把状态码存进变量再普通 `RAISE EXCEPTION`，新异常的
  `SQLSTATE` 会变成默认 `P0001`。
- 异常文本不要手写函数名常量；改名会漂移。需要标识时用 `TG_TABLE_NAME`、参数或固定错误码。
- 0 行可以是合法结果；不要用 `ROW_COUNT > 0` 作为成功条件（`REV-C05`）。

### 5.3 时间语义（ENG-23）

- `now()` 与 `transaction_timestamp()` 返回**事务开始时间**；同一次调用内多次取值不变。
- `clock_timestamp()` 返回**真实时钟**；同一次调用内多次取值会变化。
- `statement_timestamp()` 返回当前语句开始时间；长事务中与 `now()` 不同。
- 需要“整批数据用同一个时间点”时用 `now()`；需要“逐行记录真实处理时刻”时用
  `clock_timestamp()`。混用会让同一次调用内的“现在”不一致。
- `timestamptz` 存 UTC 并按会话时区显示；`timestamp` 不带时区。既有列类型不要为了“更现代”
  擅自改，改类型是契约与索引变更（`REV-C12`）。
- 只关心日期时用 `date`，不要把日期存成午夜 `timestamptz` 再比较；跨时区时会偏移。
- 以 `CURRENT_DATE` 为基准的 `INTERVAL` 时间窗，用在**落表/增量函数**时会让结果随运行日期变化，
  破坏重跑确定性（见 `01-基线规范.md` 的“可重跑性”要求）；这类函数必须由参数传入区间。
  查询或临时分析可直接使用相对窗口。

## 6. 临时表、会话状态与连接池（ENG-10）

- 临时表按会话隔离；不同会话同名不会冲突。真实风险是同会话重入/嵌套调用、连接池复用残留、
  失败分支残留与临时空间。
- 每张临时表都必须有可解释的物化理由。四项声明清单与“默认不加表”的情形只在
  `00-风格与边界.md` §3 定义，本节不重复；性能判据见 `07-性能优化规则.md` PERF-23。
- 建表前 `DROP TABLE IF EXISTS`；需要事务结束自动清理时用 `ON COMMIT DROP`（后续语句必须在
  同一事务内）。
- 临时表命名带业务前缀（如 `tmp_<domain>_<purpose>`）；这是建议形态，项目已有命名约定时
  按项目约定，但不要用 `tmp1`、`t` 这类不可检索的名字。
- 连接池 transaction 模式下，会话级状态（临时表、`SET`、advisory lock、prepared statement、
  游标、`LISTEN`）可能跨请求泄漏；函数不得依赖它们跨语句存活。
- `SET LOCAL` 限定在事务内；`SET` 会影响整个会话，慎用。

## 7. 日志、可观测性与敏感信息（ENG-12）

- `RAISE DEBUG` 用于开发细节；`RAISE INFO/NOTICE` 会进入客户端/日志，生产路径要克制。
- 不要打印完整动态 SQL、参数值、身份证/手机号/账号/连接串；需要排查时打印长度、谓词摘要、
  参数个数或脱敏哈希。
- 日志级别由 `log_min_messages`、`client_min_messages` 控制；函数内不要假设某级别一定不可见。
- 异常文本可能被调用方解析；不要把内部表名、schema、连接信息写进对外错误。
- 审计需求用表或触发器落库，不要只靠 `RAISE`。

## 8. volatility、strictness 与规划属性（ENG-13）

| 属性 | 含义 | 何时使用 | 9.4/GP |
|---|---|---|---|
| `VOLATILE`（默认） | 每次调用都可能不同，有副作用 | 写表、`nextval`、`now()`、随机 | 可用 |
| `STABLE` | 同一语句内结果稳定，不写库 | 只读查询、配置读取 | 可用 |
| `IMMUTABLE` | 相同输入永远相同输出，无副作用 | 纯计算、常量映射 | 可用；误标破坏正确性 |
| `STRICT` | 任一参数 NULL 时直接返回 NULL，不执行函数体 | 语义确实如此时 | 可用 |
| `COST` | 规划器代价提示 | 有用户提供的实测依据时 | 可用 |
| `ROWS` | 集合返回函数的预估行数 | 有统计依据时 | 可用 |
| `PARALLEL` | 并行安全标记 | `[9.6+]` | 不可用 |

- 只读函数保持默认 `VOLATILE` 不影响正确性；不要仅因“只读”强制改 `STABLE`。
- `IMMUTABLE` 函数不能读表、不能依赖 `now()`/`current_setting`/序列；否则计划可能缓存错误结果。
- `STRICT` 会改变 NULL 语义：`f(NULL)` 直接返回 NULL，不进入函数体；不要用它替代参数校验。
- `COST`/`ROWS` 没有用户提供的实测依据时不要填；填错会把计划带偏。

## 9. 依赖、迁移与部署（ENG-14、ENG-16、ENG-17、ENG-20）

### 9.1 依赖

- 函数依赖的 schema、表、类型、序列、扩展、外部表都要在部署说明中列出。
- 9.4 可用的扩展有限；`pgcrypto`、`uuid-ossp`、`pg_trgm`、`pg_stat_statements` 等需确认已安装。
- GP 6.6 的扩展集合与社区 PG 不同；`[GP-待验证]` 的扩展不要写进通用模板。
- 不要依赖 `search_path` 解析业务对象；跨 schema 调用要全限定。

### 9.2 迁移

- `CREATE OR REPLACE` 适合改函数体；改返回类型/参数类型要新建函数或显式 `DROP` + `CREATE`。
- `DROP FUNCTION` 需要处理依赖对象（视图、触发器、其他函数）；`CASCADE` 会连带删除，必须批准。
- 权限与 `search_path` 变更单独提交，便于回滚与审计。
- 迁移脚本要可重复执行：`CREATE OR REPLACE`、`IF NOT EXISTS`、幂等授权；但不要用“吞异常”
  实现幂等。注意 `CREATE INDEX IF NOT EXISTS` 是 `[9.5+]`，9.4 只能用目录查询
  （`pg_class`/`pg_indexes`）判断后再建。

### 9.3 方言

- GP 专属：`DISTRIBUTED BY`、`DISTRIBUTED RANDOMLY`、`PARTITION BY`/`SUBPARTITION BY`、
  `EXCHANGE PARTITION`、`SPLIT DEFAULT PARTITION`、`WITH (appendonly=true, orientation=column)`。
- 这些语法不要混入 PostgreSQL 通用模板；文件头注明方言与目标版本。
- 反向：不要用 PG 10+ 的声明式分区、`GENERATED AS IDENTITY`、`CREATE PROCEDURE` 替换 GP 写法。

## 10. 结构组织与可维护性（ENG-18、ENG-19）

- 单一职责：一个函数只做一件事；巨型 `p_type` 分派器要写明每个分支的目标表、业务键与测试边界。
- 分层：`f_dwd_*`/`f_dws_*`/`f_ads_*` 等层级前缀表达数据流位置；不要在一个函数里跨层写多个目标表
  而不说明。
- 复用：兄弟函数编排要说明调用顺序、失败传播与重跑影响；嵌套调用无法直接 `EXPLAIN` 整体。
- 副本：`_copyN` 必须改名、改异常文本、改头部 `*author`；不要留下指向原函数的错误信息。
- 注释：头部七字段（`F-21`）写业务语义、输入输出与返回码；不要写真实人名、联系方式、内网地址。
- 命名：遵循项目书面命名约定；无约定时遵循同仓库既有命名，不擅自引入新前缀。

## 11. 工程审查清单

- [ ] 对象类型正确：函数/触发器函数/过程（`[11+]`）选型有理由。
- [ ] 签名与返回形态是外部契约，未被擅自修改。
- [ ] 默认 invoker；definer 有理由、属主最小权限、`search_path` 固定。
- [ ] `search_path` 显式包含 `pg_catalog` 与受信 schema，`pg_temp` 放最后；对象全限定。
- [ ] `PUBLIC` 未被默认授权执行；权限证据来自 ACL，不是函数文本。
- [ ] 动态 SQL 值与标识符分离；无字符串拼接值。
- [ ] 事务边界清楚；没有函数内 `COMMIT`；异常块子事务代价已说明。
- [ ] 错误契约单一；没有 `WHEN OTHERS THEN NULL`；`SQLSTATE` 保留方式正确。
- [ ] 临时表可重入；连接池会话状态不跨请求依赖。
- [ ] 日志不泄露参数值/SQL 全文/连接信息。
- [ ] volatility/strictness 与实际行为一致；`PARALLEL` 未用于 9.4。
- [ ] 依赖（schema/扩展/序列/类型）已列出；迁移可重复执行。
- [ ] 方言已标注；GP 语法未混入通用模板。
- [ ] RLS 仅在 `[9.5+]` 且策略、索引、身份校验都具备时使用。
- [ ] 时间语义已写明：`now()`/`transaction_timestamp()` 与 `clock_timestamp()` 未混用，
      `timestamptz`/`timestamp`/`date` 的边界与转换有说明（ENG-23）。
- [ ] schema `USAGE` 与对象权限同时授予；未来对象权限按需配置默认权限（ENG-24）。
- [ ] 没有声称已运行权限查询、`EXPLAIN` 或安全扫描。
