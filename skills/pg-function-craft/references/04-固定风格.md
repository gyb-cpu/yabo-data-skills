# 固定风格

本文件定义 pg-function-craft 的固定风格。固定风格来自已完成的内部蒸馏，已脱敏为通用工程
规则：文档只保留可迁移的写法，不提供语料、个人风格资料、样例、数据库信息或来源统计。`generate`、
`rewrite`、`review` 三种模式都以本文件为风格基线；不存在从用户样例重新学习风格的独立模式。

优先级只在 `00-风格与边界.md` §6 定义，这里不重复：本文件属于第 4 层“本技能默认值”。项目已确认
的书面约定优先于本文件的命名、头部与排版；没有项目约定时按本文件执行。安全与正确性任何情况下
不可覆盖。

## 1. 命名（STYLE-01）

- 函数名：`f_` + 全小写 `snake_case`；层级、域或动作词放在 `f_` 之后，例如
  `f_<layer>_<domain>_<action>`。这是默认值；项目书面约定用 `fn_*` 等前缀时以项目为准，
  但同一仓库内必须统一（`REV-M09`）。
- 参数：`p_` 前缀，小写 `snake_case`，例如 `p_start_date`、`p_type`。
- 局部变量：`v_` 前缀，小写 `snake_case`，例如 `v_schema`、`v_row_count`。
- 游标：`cur`、`cur2`、`cur3`，不套 `v_`。
- 标识符默认不加双引号；需要保留既有大小写或特殊字符时，按原样保留，不擅自改名。
- 改写既有函数时，函数名、参数名、参数顺序与类型属于外部契约，未获批准不得改动。

## 2. 中文八字段头（STYLE-02）

每个函数的头部必须写在函数体内部：位于 `AS $function$` 之后、`DECLARE` 或 `BEGIN` 之前。不能只写在 `CREATE OR REPLACE FUNCTION` 之前。

```sql
CREATE OR REPLACE FUNCTION <schema>.f_<domain>_<action>(
    p_flag integer
    , p_start_date character varying
    , p_end_date character varying
    , p_lookback_days integer
)
RETURNS integer
LANGUAGE plpgsql
SECURITY INVOKER
SET search_path = ''
AS $function$
/*****************************************************************
*name       : <schema>.f_<domain>_<action>
*function   : <业务语义>
*input      : p_flag 0=增量 1=按日期区间, p_start_date, p_end_date, p_lookback_days=回看天数
*output     : -1参数异常, 0正常
*increment  : update_time 水位线，半开区间 [clock_timestamp()-p_lookback_days, clock_timestamp())
*author     : <原作者；新增函数写 待补充；不得伪造署名>
*CreateDate : <YYYY-MM-DD>
*UpdateDate : <YYYY-MM-DD>
******************************************************************/

DECLARE
    ...
BEGIN
    ...
END;
$function$;
```

- `*name` 必须使用 schema 全限定名，并与实际 `CREATE FUNCTION` 的函数名完全一致。
- `*function` 写简明中文业务语义，不写实现细节、SQL 写法或技术栈说明。
- `*input` 必须出现全部 `p_` 参数名并解释业务含义，不能只罗列类型；有默认值时说明默认行为。
- `*output` 必须与代码实际返回一致。返回影响行数时写 `-1参数异常, >=0影响行数`，不能照抄 `0正常`。
- `*increment` 固定保留。增量函数写明水位线、回看窗口和半开区间；非增量函数写 `不适用`。
- `*author`：改写既有函数保留原作者；新增函数写 `待补充` 或用户明确提供的作者。不得伪造署名。
- `*CreateDate` / `*UpdateDate` 使用 `YYYY-MM-DD`；新建函数两者一致，修改函数追加当天 `UpdateDate`。
- 头部是文档承诺：`*output` 声明的返回码和分支必须在代码中可达。
- 普通 `--` 注释只在脚本前导中存在，不会被 `pg_get_functiondef` 导出；因此函数头必须是函数体内的块注释，部署后导出仍必须可见。

## 3. 排版（STYLE-03）

完整规则见 `06-SQL排版规范.md`，固定默认值如下：

- 4 空格缩进，逐级 +4；禁止 tab；无行尾空白；文件尾单个换行；UTF-8 无 BOM；LF。
- 关键字大写（`SELECT`、`FROM`、`WHERE`、`BEGIN`、`IF`、`RETURN`）；类型与内置函数小写
  （`bigint`、`format`、`coalesce`）；`LANGUAGE` 大写、语言名 `plpgsql` 小写。
- 前置逗号：列清单、函数参数、`SELECT` 列表都写成 `,col` 起行，首项不带逗号；同一文件
  不得混用前置与后置逗号（存量文件局部转换允许过渡，见 `06-SQL排版规范.md` §3.2）。
- 子句关键字独占一行、与语句同列；子句内容缩进 +4；`SELECT` 列表一项一行。
- 不用多空格做列对齐；行宽默认 ≤100 字符，长 `IN` 列表与宽列清单 ≤120。
- `AND` / `OR` 起行，与首个谓词同列；混用时加括号。
- 段注释用 `-- 1.`、`-- 2.` 编号，与语句同列；行尾注释前至少 2 空格。
- 美元引用默认 `$function$`；正文出现同名标签时改用 `$fn$` 或 `$sql$`，同一函数内成对一致。

排版是前置步骤，不是审查结论。格式化只改空白、换行、关键字大小写、标识符引号与注释位置，
不得改变 SQL 结构、语句顺序、键、值或字符串内容。

## 4. 函数结构（STYLE-04）

- 统一使用 `CREATE OR REPLACE FUNCTION ... RETURNS ... LANGUAGE plpgsql AS $function$`；
  过程与触发器函数按目标版本支持情况调整，但块结构保持一致。
- 函数体按 `DECLARE` → `BEGIN` → `EXCEPTION` → `END` 组织；变量在 `DECLARE` 中一次声明，
  不在 `BEGIN` 中临时追加。
- 用 `-- 1.`、`-- 2.` 分段：参数校验、准备、主处理、落表、返回。分段注释与语句同列。
- SQL 结构化：优先 CTE 或子查询分层；显式列清单，不写 `SELECT *`；显式 `JOIN` 条件；
  多表查询给列加表别名限定。
- 对**返回标量状态码**的 ETL/落表函数：入口校验参与谓词的参数（`IS NULL`、空串、日期区间
  倒置），失败时 `RETURN -1` 并写明原因，成功路径必须能到达 `RETURN 0`。0 行可以是合法结果，
  不用 `ROW_COUNT > 0` 判成功。`SETOF`/`RETURNS TABLE`/触发器/过程不适用返回码契约，按
  `09-工程与函数结构规范.md` ENG-11 与 `10-PLpgSQL语法与函数形态.md` 的返回形态规则处理。
- 异常先捕获具体条件（`WHEN unique_violation` 等）；必须兜底时用
  `GET STACKED DIAGNOSTICS` 取 `RETURNED_SQLSTATE` 与 `MESSAGE_TEXT`，再 `RAISE;` 原样重抛，
  或 `RAISE EXCEPTION ... USING ERRCODE = v_state`。禁止 `WHEN OTHERS THEN NULL`。
- 写表函数默认 `VOLATILE`，不必显式声明；只读函数也不必强行标 `STABLE`。`IMMUTABLE` 只在
  可证明时使用。
- 头部、签名、返回码、异常文本、权限属性与 volatility 属于外部契约；改写时未获批准不得改动。

## 5. 集合式优先与临时表（STYLE-05）

- 优先用一条集合式 SQL 完成处理，而不是逐行循环。确需逐行时，限定为分区 DDL、逐条修复或
  外部副作用，并写明行数上界、批大小与锁策略。
- 临时表只在有物化理由时使用。四项声明清单（为什么必须物化、被引用几次、生命周期、清理与
  失败路径）见 `00-风格与边界.md` §3，本文件不重复。
- 只引用一次的中间结果用子查询或 CTE，不为拆短 SQL 新增临时表；已有同粒度临时表时复用。
- 每张临时表写明四项清单；命名带业务前缀，创建前先 `DROP TABLE IF EXISTS`。
- 覆盖式落表把 `DELETE` + `INSERT` 当作一个作用域：删除谓词必须覆盖插入可能产生的全部行，
  或明确写出 staging 过滤丢掉了哪些行。整表刷新要单独声明恢复边界与锁影响。

## 6. 日期与时间谓词（STYLE-06）

完整判据与反例见 `00-风格与边界.md` §4；这里只给默认写法：

- 列侧裸露，右侧显式类型或参数：`col >= p_start_date::date`，不写 `col::date >= ...`。
- 列已经是 `date` 时不再写 `::date`；参数是文本时在参数侧转换。
- 日期/时间列优先半开区间：`>= p_start AND < p_end + 1`；`BETWEEN` 的闭区间语义先与业务确认。
- 相对时间窗：查询可直接用；落表/增量函数必须由参数传入（`09` ENG-23）。
- 只有列类型确实不是日期且没有可索引的等价写法时，才允许列侧 cast，并标 `plan-required`。

## 7. 安全与动态 SQL（STYLE-07）

- 默认 `SECURITY INVOKER`。必须用 `SECURITY DEFINER` 时，`search_path` 按
  `01-基线规范.md` 的二选一写法固定（`pg_catalog, <可信schema>, pg_temp` 或 `''` + 全限定）；
  对象全部 schema 限定；复核 `PUBLIC` 执行权限与属主权限；函数 owner 使用最小权限角色。
- 动态 SQL 把标识符与值分开：标识符用 `format('%I', ...)`、白名单或系统目录校验；值用
  `EXECUTE ... USING` 绑定，字面量用 `%L`。不得把不可信值拼进 SQL 文本。
- 不写死跨环境 schema；schema 作为参数或集中配置传入，不散落在 SQL 字符串里。
- 不输出、不落盘主机、端口、账号、口令、库名、连接串与 ACL 明细。

## 8. 引擎与版本（STYLE-08）

- 默认面向**原生 PostgreSQL 12+** 编写；PostgreSQL 13+ 专属语法先确认目标版本，未确认时标
  `待验证`，不写进通用模板。
- Greenplum 6.6 / PostgreSQL 9.4 仅作为可选兼容模式：只有用户显式声明目标为 GP 或低版本 PG
  时，才按其降级边界执行；GP 专属构造（`DISTRIBUTED BY`、`SPLIT DEFAULT PARTITION`、
  `EXCHANGE PARTITION`、`pg_partition_rule`、`appendonly` 等）必须标注方言，不静默混入原生 PG。
- 具体特性与最低版本**只查一处**：`10-PLpgSQL语法与函数形态.md` §1.1。本文件不维护版本清单。

## 9. 性能分析边界（STYLE-09）

- 只做静态 SQL 分析；不连接数据库，不执行 `EXPLAIN`，不采集运行时数据。
- 每条性能陈述带一个标签：`static-risk`、`inferred`、`plan-required`、`workload-required` 或
  `not verified`；未实测不得写“更快”“已验证”“实测通过”。
- 静态信号包括：过滤列上的函数或 cast、隐式类型转换、`SELECT *`、无界结果集、重复扫描、
  只引用一次的临时表、无物化理由的 staging、循环内逐行 DML、动态 SQL 文本膨胀。
- 需要执行计划或负载才能定论的事项，写成待验证项，由用户在目标库执行；本技能不代为执行。

## 10. 冲突与例外（STYLE-10）

- 冲突优先级只在 `00-风格与边界.md` §6 定义；本节不另立顺序。
- 项目已确认的书面约定可以覆盖命名与排版；覆盖后的例外逐条登记理由，不藏进“更干净”的代码里。
- 安全与正确性不可覆盖，也不可降级。
- 发现固定风格与目标版本语法冲突时，保留语义与契约，改用版本可用的等价写法，并标注差异。
