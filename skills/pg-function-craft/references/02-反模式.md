# 反模式

本文件分两层：

- **A 层（`AP-01`…`AP-10`，含 `AP-01b`）**：常见 ETL/落表函数里高频出现、但生成时**不能继承**的写法。
  这些条目描述的是“模式”，不针对任何个人，也不附带语料计数或样例路径。
- **B 层（B-01…B-08）**：与具体业务无关的通用安全/正确性反模式，用于没有输入或输入未覆盖的场景。

A 层不是“个人风格”。看到某种写法频繁出现，只能说明它常见，不能说明它正确；评审时仍以
`references/01-基线规范.md` 的安全与正确性约束为准。

## A 层：落表/ETL 常见反模式

| ID | 常见写法 | 为什么不能继承 | 生成时应改为 |
|---|---|---|---|
| AP-01 | 动态 SQL 值拼接：`v_where := v_where \|\| ' AND info_date >= ''' \|\| p_start_date \|\| ''''` | 参数值直接进入 SQL 文本，注入面打开；日期/字符串靠手工补引号，类型与转义都不可靠 | `EXECUTE ... USING` 绑定值；标识符用 `format('%I', ...)`；字面量用 `%L` |
| AP-01b | `format()` 只用 `%s`：`format('SELECT MIN(%s) ... FROM %s ...')` | `%s` 不做标识符引用，表名/列名含特殊字符或来自参数即失效、可注入 | 标识符一律 `%I`；值用 `USING` 或 `%L` |
| AP-02 | `WHEN OTHERS THEN RAISE EXCEPTION '<fn>: %', SQLERRM` | 比 `WHEN OTHERS THEN NULL` 好，但仍丢失 `SQLSTATE`、出错语句与参数上下文；函数名是手写常量，改名即漂移；把可恢复错误与程序缺陷压成同一出口 | 先捕获具体 `WHEN <condition>`；必须兜底时用 `GET STACKED DIAGNOSTICS` 保留 `SQLSTATE`/`MESSAGE_TEXT`，并带关键参数 |
| AP-03 | 无谓词 `DELETE FROM 表;`，或删除范围大于随后可重建的范围 | 函数体没有显式事务控制：`DELETE` 与 `INSERT` 都在调用方事务（或语句级子事务）里执行，`INSERT` 抛异常且未被捕获时会中止该（子）事务、已删除的行随之回滚。真实风险是删除范围大于可重建范围，或把 `DELETE` 放在 `EXCEPTION` 块外、把易失败的 `INSERT` 放在块内吞掉异常后返回成功，此时插入被回滚而删除可能随外层提交。序列与 identity 不随之回滚 | 必须带 `WHERE`；确需整表重建就显式写 `TRUNCATE`/分区交换，并写明业务范围、恢复边界与失败窗口 |
| AP-04 | 头部承诺 `-1参数异常`，但无 `IS NULL` 校验；把 `RETURN -1` 注释掉 | 调用方按文档传 `NULL` 会静默跑成空结果或全量；0 行本身可能合法（空日期区间、源表无增量），但函数无法区分“无数据”与“参数错误”，返回 `0` 不可诊断 | 入口显式校验参与谓词的参数（`IS NULL`、空串、区间倒置），失败 `RETURN -1` 并说明原因；不要用 `ROW_COUNT > 0` 判成功。该契约只适用于返回标量状态码的函数；`SETOF`/触发器/过程按 `09` ENG-11 与 `10` 处理 |
| AP-05 | 循环内逐行 `OPEN cur FOR EXECUTE ...; LOOP; FETCH ...; EXECUTE v_sql;` | 逐行 DML/DDL，行数一多就放大往返与锁持有；`EXECUTE` 在循环里重复解析 | 先集合化到临时表，再用单条 `INSERT`/`DELETE`；确需逐行（分区 DDL）时写明行数上界与批大小 |
| AP-06 | 临时表只 `DROP`+`CREATE`，无 `ON COMMIT DROP`，且一次函数里堆很多张 | 同会话内残留：连接池复用会累积临时表，重复/嵌套调用可能命中同名旧表；失败回滚会撤销本次建表，但同会话早先留下的同名表仍可能被后续分支误用。临时表按会话隔离（各自 temp schema），不同会话互不可见，因此风险模型不是“跨会话并发冲突” | 新代码可用 `CREATE TEMPORARY TABLE ... ON COMMIT DROP`（确认后续语句仍在同一事务内），或函数末尾显式 `DROP`；改写既有函数时保持原写法，不擅自加 `ON COMMIT DROP`；命名带业务前缀；每张表都要有物化理由（见 `00-风格与边界.md` 第 3 节） |
| AP-07 | 硬编码 `db_<省>.` / `dw_<省>.` schema | 换库、换 schema 命名、上测试环境即失效；`db_` 前缀 schema 常被导出过滤排除，本身不在版本管理内 | schema 作为参数或集中配置，不要散落在 SQL 字符串里 |
| AP-08 | Greenplum 专属 DDL：`ALTER TABLE ... SPLIT DEFAULT PARTITION ...`，或非标准 `RETURN EXCEPTION` | 原生 PostgreSQL 无此语法，一调用即报错；且动态执行时静态审查不易发现 | 标注方言；通用模板不出现；需 GP 时单独维护并按方言分支 |
| AP-09 | `RAISE INFO '%', v_sql` 打印整段 SQL | 生产日志膨胀；SQL 含参数值，可能泄露业务数据 | 改 `RAISE DEBUG`，或只打印长度/关键谓词，由 `log_min_messages` 控制 |
| AP-10 | 无 `search_path`，动态 SQL 里大量非限定对象名 | 当前是 `SECURITY INVOKER`，风险有限；一旦改成 `SECURITY DEFINER`，未显式限定 schema 的表名会按调用方 `search_path` 解析，而关系名解析时 `pg_temp` 隐含排在最前，可写的 `public` 也常在其中，都可能被劫持 | 保持 invoker；改 definer 必须显式 pin `search_path = pg_catalog, <trusted_schema>, pg_temp`（`pg_temp` 放在**最后**），并限定对象名、收紧 `PUBLIC` 执行权限。只写“排除 `pg_temp`”不够 |

### A 层补充：归因漂移

复制函数（`_copyN`）后没有同步修改异常文本里的函数名，会让日志指向另一个函数。
不要用异常信息反查是哪个函数失败；复制函数时必须同步改这一段。

### 契约补充：成功码不等于写入

`RETURN 0` 只表示分支执行完毕，调用方无法区分“无数据”与“成功”。注意 0 行可以是合法结果
（空日期区间、源表无增量），不能把 `ROW_COUNT > 0` 当成功条件；只有业务契约明确要求区分
“无数据/失败”时，才需要行数校验。

## B 层：通用反模式

| ID | 模式 | 默认分类 | 要求 |
|---|---|---|---|
| B-01 | `WHEN OTHERS THEN NULL` 或假成功返回 | correctness risk | 报告；仅在明确批准的契约下保留 |
| B-02 | 动态 SQL 值拼接（与 AP-01 同源，跨语料通用） | security risk | 改用 `USING`；标识符用 `%I` |
| B-03 | `SECURITY DEFINER` 且无可信 `search_path` | security risk | 阻断，直到审查并修复 |
| B-04 | 读表/时间/随机状态却标 `IMMUTABLE` | correctness risk | 核实依赖，修正 volatility |
| B-05 | 行循环里跑 SQL | performance risk | 评估集合化重写、副作用、基数、锁与批大小 |
| B-06 | 在带索引的过滤列上套函数或 cast（含不必要的 `col::date`） | plan-required | 先改成裸列 + 右侧显式类型；必要时由用户查表达式索引并执行 `EXPLAIN`；不得承诺更快 |
| B-07 | 无界 `SELECT *` 或集合物化 | performance/contract risk | 显式列或流式返回 |
| B-08 | 用宽异常块做正常分支 | correctness/performance risk | 用显式谓词；只捕获可恢复情况 |

## 不要误判为反模式

- **未声明 volatility**：写表函数默认 `VOLATILE` 正确。只读函数保持默认 `VOLATILE` 也不影响
  正确性；`STABLE` 只是优化器提示，只在函数不写库、且同一条语句内结果稳定时才标。
- **`RETURNS smallint` 而非 `void`**：返回码是外部契约，改成 `void` 会破坏调用方。
- **`WHEN OTHERS` 的存在**：问题在“只包一层 `SQLERRM`”（AP-02），不在“有兜底”。
- **`DELETE` + `INSERT` 而非 upsert**：分区级覆盖的合理选择；除非确认唯一键且语义等价，不要改
  `ON CONFLICT`。但删除范围要按业务范围核对，不能只看日期谓词。
- **`WHERE 1 = 1`**：动态谓词拼接的常见起点，本身无害；问题在拼接方式（AP-01）。
- **`p_flag = 0 THEN ... ELSE ...`**：这是模式开关，不是死代码——除非能证明某分支不可达。
- **`coalesce` 兜底与 `INTERVAL` 时间窗**：会改变 NULL 与边界语义（哨兵值、右开/闭区间、
  `date` 与 `timestamp` 混用），不是纯版式；改写必须做新旧结果对比，见 `05-重写协议.md`。
